# 004：优先使用静态图组合

## 决策

子图复用先通过 `GraphBuilder.include()` 在构建阶段完成命名空间合并，不在 Machine 中
引入嵌套运行器或 `SubGraphManager`。

## 原因

- 子图仍然是普通 Graph，校验、快照和运行语义只有一套。
- Action、Guard 和元数据可以复用，节点和迁移 ID 通过前缀隔离。
- 外部工具可以直接检查合并后的完整图，不需要理解运行时嵌套关系。
- 只有当真实场景需要独立子运行生命周期时，才再设计运行时子图协议。

`include()` 是静态定义组合，不承诺分布式并行、独立持久化或自动返回父图；这些能力
仍由 Fork/Join 或未来的执行协议负责。
