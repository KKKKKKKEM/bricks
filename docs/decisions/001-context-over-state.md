# 001：使用 Context 表达运行状态

## 决策

Bricks 不再定义一个与运行上下文并列的 `State` 对象。一次运行的动态信息统一放在
`Context` 中，流程位置使用 `Context.node_id`，生命周期使用 `Context.status`。

## 原因

- 避免业务数据、流程位置和生命周期分散在多个可变对象中。
- 让快照天然对应一次运行的完整恢复上下文。
- 保留未来在 `Context.data` 中承载不同领域数据的空间。
- 不把“状态机”这个建模视角强加给工作流、响应式和并行语义。

`Status` 仍然存在，但它只表示运行生命周期，不是第二套业务状态模型。
